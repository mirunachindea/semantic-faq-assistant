Semantic FAQ Assistant field guide

A question comes in over HTTP. The service finds the closest entries in a curated FAQ, decides whether one of them really answers it, and replies from the FAQ, from an LLM, or with a polite refusal. This page explains every component that makes that happen and why it is built that way.

One request, end to end

The fastest way to understand the project is to follow a single call to POST /ask-question. These steps run in this order for every request.

  1. FastAPI receives the request api/routers/questions.py · middleware in main.py

    A request ID is attached for logging. The body is validated: user_question must be a non-blank string, no extra fields, at most 500 characters.

  2. The bearer token is checked api/dependencies.py → get_token()

    Injected with Depends(get_token). A missing or wrong token returns 401 before any work happens. Tokens are compared in constant time.

  3. The assistant service takes over services/assistant.py → FAQAssistant.ask()

    It creates a routing context for the question and hands it to the router. It does not search yet; search runs only if a rule needs it.

  4. The input guard inspects the text routing/router.py → InputGuardRule · guardrails/input_guard.py

    Known prompt-injection patterns ("ignore previous instructions", "reveal your system prompt", chat-template tokens…) are refused here, before any paid API call.

  5. Hybrid search finds candidate FAQ entries retrieval/search.py → HybridSearcher · storage/postgres.py

    The question is embedded once, compared with two vectors per FAQ entry in pgvector, and the top 5 are re-scored with a small keyword-overlap bonus.

  6. The router decides where the question goes routing/router.py → SemanticRouter

    A very confident match goes straight to the FAQ. Otherwise an LLM judge looks at the candidates and chooses: this FAQ entry, the general LLM, or compliance.

  7. An answering agent writes the reply agents/responders.py

    The FAQ agent rephrases the stored answer for the user's wording. The LLM agent writes general guidance. The compliance agent returns a fixed sentence.

  8. The output guard checks the reply guardrails/output_guard.py

    Empty text, leaked prompts or secrets are rejected. For FAQ answers the original curated text is used instead; for LLM answers a safe fallback message.

  9. The response is returned api/schemas.py → AskQuestionResponse

    Always the same shape: source, matched_question ("N/A" when none), answer, plus category and similarity_score.

Authorization: Bearer local-dev-token
{"user_question": "Where do I download my invoices?"}

The semantic router

The router is the "decision function" the challenge asks for. It is a list of rules checked in order. Each rule either makes a decision or passes (returns None) so the next rule can try. The first decision wins.

This shape was chosen so new policies are easy to add. A rule like "billing questions from free users go to a human" is one small class inserted into the list; nothing else changes. A test in tests/unit/test_router.py does exactly that.

1

InputGuardRule

Regex and normalisation check for injection and abuse. Runs before search, so a blocked question costs zero API calls.

complianceelse pass
2

HighConfidenceMatchRule

If the best search score is at least 0.85, answer from that FAQ entry without asking an LLM. Saves time and tokens on obvious matches.

localelse pass
3

LLMRouterRule

The agentic step. The LLM sees up to 3 candidates (score ≥ 0.40), labelled c1–c3, and returns a validated RouterVerdict: route, which candidate, whether it is an injection, and a one-line reason. It judges intent, not shared words, and decides if the topic is in scope (IT and account support).

localllmcompliancepass on error
4

ScoreFallbackRule

Safety net for when the LLM judge is down, returns malformed output, or names a candidate that was never offered. Uses the score alone: ≥ 0.60 answers locally, otherwise the LLM.

localllm

The code lives in src/faq_assistant/. It is grouped into layers. Inner layers never import outer ones: the router knows nothing about HTTP, and the search code knows nothing about OpenAI.

Foundation

Settings

config.py
Does
Declares every setting as a typed field with a default: models, API key, database URL, thresholds, tokens, Celery URLs. Values come from environment variables or .env, e.g. CHAT_MODEL=gpt-4.1-mini.
Why
Pydantic validates at startup, so a typo like ACCEPT_THRESHOLD=abc fails immediately instead of during a request. It also checks the thresholds are in a sensible order (candidate ≤ fallback ≤ accept).
Look at
llm_api_key accepts either LLM_API_KEY or OPENAI_API_KEY. Tokens are SecretStr, so they never print in logs.

Domain models and errors

domain/models.py domain/errors.py
Does
Defines the shared vocabulary: FAQItem, SearchHit (with dense, lexical and combined score), Route, RouteDecision, AssistantAnswer. And the exception family: UpstreamServiceError, UpstreamRateLimitError, VectorStoreError, and so on.
Why
Every layer speaks in these types, so no layer depends on OpenAI or FastAPI classes. The API layer converts domain errors to HTTP codes in one place.
Look at
FAQItem.document_text builds the "Topic / Question / Answer" text that gets its own embedding.

Composition root

container.py
Does
The one place that creates concrete objects: picks Postgres or in-memory storage, builds the chat model and embeddings, the chains, the router with its rules, and the three agents, then wires them into FAQAssistant.
Why
Everything else receives its dependencies as arguments. Tests pass in fakes (a fake embedder, fake chains) and the whole app runs without network access. Swapping a store or model means changing this file or a setting only.
Knowledge base and storage

Cleaning rules

knowledge_base/cleaning.py
Does
Normalises text (unicode, dashes, zero-width characters, whitespace) and runs small quality rules over each entry. Each rule can reject an entry, flag it, or fix it. Details in Cleaning the FAQ data.
Why
The provided data is deliberately messy. Bad entries would otherwise match real questions and serve useless or unsafe answers.
Look at
to_search_text() is applied to FAQ questions and to user questions alike, so both are embedded in the same form.

Loader and curation

knowledge_base/loader.py
Does
Reads the JSON file, validates its shape, runs the cleaning rules, removes duplicates and gives each entry a stable ID derived from its collection and question.
Why
Stable IDs mean the same question always maps to the same database row, which is what makes incremental updates possible. Rejected entries are reported, not silently dropped.

Incremental indexer

knowledge_base/indexer.py
Does
Computes a SHA-256 content_hash for each entry (covering the embedding model and all embedded text), compares with hashes already stored, and embeds only entries that are new or changed. Optional prune deletes entries no longer in the source.
Why
Token efficiency. Re-running a sync on unchanged data makes zero embedding calls. Editing one answer re-embeds only that entry. Updates never delete data unless asked.
Look at
It also checks the provider returned the right number of vectors of the right length before storing anything.

Vector stores

storage/base.py storage/postgres.py storage/memory.py
Does
base.py defines the VectorStore interface (create collection, upsert, delete, search, ping). The Postgres version stores items in a faq_items table with two VECTOR(1536) columns and HNSW cosine indexes. The memory version does the same with numpy for tests and quick local runs.
Why
pgvector keeps text, metadata and vectors in one database with real SQL. The interface means another vector database could be added without touching search or routing code.
Look at
A collections table records which embedding model each collection used. Mixing models is refused, because vectors from different models can't be compared.
Search and LLM access

Hybrid searcher

retrieval/search.py
Does
Embeds the question, asks the store for the top 5 by cosine similarity, adds a bounded keyword bonus, and sorts. Explained in How search scores work.
Why
Embeddings capture meaning ("I want my money back" finds "Can I get a refund?"). The keyword bonus rewards exact terms like "2FA" or "passkeys" that embeddings sometimes blur.

Model factory

llm/factory.py
Does
Builds the chat model and embedding model through LangChain's init_chat_model and init_embeddings, using provider and model names from settings, with timeout and retries.
Why
Switching to another model or provider (Anthropic, Ollama, Azure…) is a setting change, as long as the matching langchain-<provider> package is installed.

Prompts and chains

llm/prompts.py llm/chains.py
Does
Three prompts: the router judge, the general LLM answer, and the FAQ personaliser. chains.py combines each prompt with the model into a LangChain runnable. The router uses with_structured_output(RouterVerdict) so the reply must fit a Pydantic schema.
Why
Other code only sees typed runnables. A prompt, a model or a whole chain can be replaced on its own. In tests, a runnable is just a Python function.
Look at
User text always sits inside <user_question> tags in the user message and is described as untrusted. Each system prompt carries a random canary string used to detect leaks.

Error translation

llm/errors.py
Does
upstream_call() wraps every model call. Any failure becomes UpstreamServiceError; rate limits (any provider's *RateLimit* error or HTTP 429) become UpstreamRateLimitError.
Why
The rest of the code handles two error types instead of dozens of provider-specific ones.
Decision and answer

Semantic router

routing/router.py
Does
Runs the four rules described in The semantic router. RoutingContext runs search lazily and at most once per request, shared by all rules.
Why
Rules can be added, removed or reordered. The LLM verdict is treated as untrusted: an unknown candidate ID or malformed output makes the rule pass instead of guessing.

Answering agents

agents/responders.py
Does
LocalAnswerAgent rewrites the stored answer to fit the user's wording, using only facts in it. LLMAnswerAgent gives general, platform-neutral guidance. ComplianceAgent returns “This is not really what I was trained for, therefore I cannot answer. Try again.”
Why
The curated FAQ is the source of truth, so if personalisation fails the original answer is returned. The compliance agent never calls a model, so it can't be talked out of its answer and doesn't reveal which check fired.

Assistant service

services/assistant.py
Does
The small orchestrator: create context, route, call the agent for the chosen route. On startup it checks that every route has an agent.
Interfaces

HTTP API

main.py api/
Does
main.py creates the FastAPI app, builds the container at startup and closes it at shutdown, and adds request-ID logging. api/routers/ holds the endpoints; api/schemas.py the request and response shapes; api/dependencies.py the auth; api/errors.py the error-to-status mapping.
Endpoints
POST /ask-question · GET /health · GET /health/ready · GET /admin/collections · POST /admin/collections/{name}/items · GET /admin/tasks/{id}. Admin routes need an admin token.

Admin CLI

cli.py → faq-admin
Does
Manages the embeddings database: validate, init-db, sync (with --prune, --force, --async, --collection), list, delete-collection, plus search, ask and evaluate for debugging and measurement.

Background worker

worker/celery_app.py worker/tasks.py
Does
A Celery task, faq.sync_collection, runs curation and embedding outside the web request. Redis is the broker. Rate-limit errors retry with exponential backoff.
Why
Embedding a large upload can take a while; the API returns 202 with a task ID immediately. Because sync is idempotent (hash-based), a retry or redelivery is safe.

Evaluation

evaluation.py · data/eval/eval_set.jsonl
Does
Runs 41 labelled questions and reports hit@1, hit@5, MRR, a threshold sweep, and (with --with-router) routing accuracy. Query embeddings are fetched in one batch to save requests.
Why
Thresholds were chosen from measurements, not guesses. See Measured quality.

How search scores work

Two vectors per FAQ entry

Each entry is embedded twice. The question vector is the cleaned question alone; it is best for matching a question to a similar question. The document vector is “Topic: profile / Question: Edit avatar? / Answer: Open Profile, tap your avatar…”; it helps short keyword entries where the meaning is in the answer. The search takes the higher of the two similarities.

Keyword bonus that can only help

score = dense + 0.2 × lexical × (1 − dense)

dense is the cosine similarity above. lexical is the share of the user's meaningful words (stop-words removed, plurals folded) that also appear in the FAQ question or category.

Worked example: dense = 0.80 and every word matches (lexical = 1.0) gives 0.80 + 0.2 × 1.0 × 0.20 = 0.84. With no shared words the score stays exactly 0.80. A paraphrase is never punished, and the score can never exceed 1.

Guardrails

The system will face jailbreak attempts, so there are several independent layers. Each one catches what the others miss.

LayerWhat it stopsFile
Request validationWrong types, extra fields, blank or overlong questionsapi/schemas.py
NormalisationHidden zero-width characters and look-alike letters used to dodge filtersguardrails/input_guard.py
Pattern filter“Ignore previous instructions”, “reveal your system prompt”, “you are now…”, DAN / developer mode, <|im_start|>, [INST], system:, long base64 blobsguardrails/input_guard.py
LLM judgeReworded attacks the patterns miss (is_prompt_injection flag)routing/router.py
Prompt designUser text is fenced in tags and labelled untrusted; the rules say never to reveal instructions or produce secretsllm/prompts.py
Canary stringA random marker in every system prompt; if it shows up in an answer, the answer is thrown awayllm/prompts.py
Output checkEmpty replies, prompt leaks, API keys and private keys, overlong textguardrails/output_guard.py
AuthenticationAnonymous use; admin actions need a separate tokenapi/dependencies.py

Every refusal uses the same compliance sentence, so an attacker can't tell which layer caught them. The reason is logged on the server with the request ID.

Glossary

Embedding
A list of numbers (1536 here) representing the meaning of a text. Texts with similar meaning get similar lists.
Cosine similarity
How closely two embeddings point in the same direction; near 1 means very similar meaning.
pgvector / HNSW
A Postgres extension that stores embeddings, and the index type that finds nearest neighbours quickly.
hit@k
Share of questions whose correct FAQ entry appears in the top k results.
MRR
Mean reciprocal rank: 1 if the right answer is always first, 0.5 if always second, and so on.
Prompt injection
User text that tries to override the model's instructions, e.g. “ignore previous instructions”.
Structured output
Making the LLM reply in a fixed JSON schema that is validated, instead of free text.
Runnable / chain
LangChain's unit of work: prompt → model → parser, callable with ainvoke().
Idempotent
Running it twice has the same effect as running it once; safe to retry.
Content hash
A fingerprint of an entry's text; if it hasn't changed, the entry isn't re-embedded.
